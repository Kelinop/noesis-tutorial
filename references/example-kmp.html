01PROB. 原始问题 · BRUTE FORCE

01BF 的浪费：把已经验证过的字符再比较一遍

字符串模式匹配：在主串 S（长度 n）中找模式串 T（长度 m）首次出现的位置。最直观的是 BF（Brute Force）：从 S 的每个位置出发逐字符比较，失败则 S 指针回退到本轮起点 +1、T 指针归 1。用具体构造输入 S = "aaaaab"、T = "aaab" 走一遍（见图 1）：

原因

BF 失败时回退主串指针，丢弃已匹配部分的结构信息——「aa」已被验证，却从头再比。

↓
压力

最坏 O(n×m)：S = "aaaaaaaaaab"、T = "aaaab" 这类「长前缀重复」的输入让 BF 每轮都几乎走完全程。

↓
设计

KMP：利用模式串自身「前缀 = 后缀」的结构，失败时主串指针不动，模式串指针跳到 next[j]——已验证的部分由模式串自己记住。

BF 把已经匹配过的字符重新比较了一遍——浪费不在比较，在回退。
本质模型 · ESSENCE MODEL

模式串替主串记住进度

02

当 S[i] 与 T[j] 失败时，我们已经知道 S[i−j+1 .. i−1] = T[1 .. j−1]。如果模式串自己存在「前 k−1 个字符 = 最后 k−1 个字符」的重叠，把模式串右滑到那个位置，重叠段自动对齐到 S 已匹配的部分——不需要重新比较，直接从 S[i] 与 T[k] 继续。主串指针 i 从不回退，回退的只有模式串指针。

这个模型的适用边界：主串不回退依赖 O(m) 的前缀信息预处理，并付出 O(m) 额外空间。单次匹配也能获得 O(n+m) 的最坏时间界，但常数开销是否值得，取决于输入规模与失配形态；同一模式串反复使用时，预处理成本还能被多次摊还。流式输入中无法回退主串时，这个模型尤其有价值。

03NEXT 机制 · NEXT 数组

03next 数组：定义、双法手算与代码

考查方式：next 数组可单独要求手算，也可作为字符串匹配综合题的第一步；常见变式是给 next 反推模式串（第 07 节变式 2）。具体频率与分值以历年真题和当年试卷为准，本页不据此推断命题权重。

定义 · 严蔚敏约定 1-indexed

next[1] = 0（哨兵值）；next[j] = T[1 .. j−1] 的最长相同前后缀长度 + 1；无相同前后缀（长度 0）时 next[j] = 1。

物理含义：当 T[j] 失败时，模式串指针应跳转到的位置——跳转后 T[1 .. next[j]−1] 与 S 对应位置的匹配已由前缀-后缀结构保证，无需重新验证。

手算有两种方法，考场推荐双法互验：方法一（定义法）逐个位置求「T[1..j−1] 的最长相同前后缀 + 1」，适合首次推导；方法二（递推法）由 next[j−1] 推出 next[j]（next[j] 要么是 next[j−1]+1，要么沿着 next 链回退），适合速算。下面用 T = "ababa" 走一遍方法一（外层是语境、内层是内容的嵌套面板）：

「最长相同前后缀」本身值得一张图（见图 2）：以 T = "aaab" 的失败位置 j = 4 为例，T[1..3] = "aaa" 的最长相同前后缀是 "aa"（长度 2），所以失败后直接跳到 j = 3——前两个字符不用重比。

易错 · 两个核心陷阱

① 在严蔚敏 1-indexed 约定中，next[j] 是“最长相同前后缀长度 + 1”——"aaa" 的最长相同前后缀是 "aa"（长度 2），因此 next[4] = 3；写成 2 会造成整体下标错位。② 该约定下 next[2] 恒为 1：T[1..1] 只有一个字符，没有真前后缀，这是定义推论而非需要记忆的特例。

有了 next 数组，匹配主循环只有三行（见图 3）。注意 j == 0 这个条件：它是哨兵——当 j 回退到 0 时，i、j 同时前进，「主串前进、模式串从头开始」不需要单独的代码路径。

BLUEPRINT CALLOUT · 哨兵 j = 0

j = 0 不是「比较第 0 个字符」，是「模式串已无重叠可退」的信号——此时 S[i] 不可能与任何 T 前缀匹配，只能 i、j 同时 +1，从 T[1] 重新开始。没有这个哨兵，就要多写一个分支处理「回退到头」的情况。

05NEXTVAL 机制 · NEXTVAL 优化

05消除注定失败的比较：继承链

考查方式：给出 next 要求补 nextval，或给出 nextval 反推继承链；前者检验递推规则的执行，后者检验是否理解“继承的是优化后的值”。具体题型与分值以试卷为准。

next 数组还藏着一处冗余：当 T[j] == T[next[j]] 时，S[i] ≠ T[j] 必然意味着 S[i] ≠ T[next[j]]——跳过去之后那次比较注定失败，却仍然在执行。nextval 的规则是：把注定失败的跳转「继承」掉（见图 5）。

优化规则 · nextval 递推

若 T[j] ≠ T[next[j]]：nextval[j] = next[j]（跳转有效，保持原值）。

若 T[j] == T[next[j]]：nextval[j] = nextval[next[j]]（跳过注定失败的比较，直接继承）。

nextval[1] = 0（哨兵不变）。注意：继承的是 nextval 的值，而不是 next 的值；混淆两者会丢掉前面已经完成的跳过。

反向极端：模式串 T 无任何字符重复（如 "abcdef"）时，next 与 nextval 完全相同——每个跳转都有效，优化收益为零。这正是「优化不是免费的定理，是条件触发的增益」：nextval 消除的是结构冗余，结构不冗余时它什么都不做。

06COMPLEX 权衡 · COMPLEXITY

06O(n+m)：i 单调为何给出线性时间界

考查方式：复杂度常以概念判断（O(n+m) 与 O(n×m)）或摊还论证出现。若题目要求解释线性时间界，核心是说明 j 的总回退次数被前进次数摊还，而不是只背结论。

为什么主串指针不回退就一定是线性的？摊还论证：i 每轮要么 +1（匹配或哨兵），要么原地等待 j 回退；而 j 每回退一次都跳到更小的位置（next[j] < j），且 j 的前进（+1）次数 ≤ i 的前进次数 ≤ n——所以 j 的总回退次数 ≤ 总前进次数 = O(n)。匹配循环 O(n)、预处理 O(m)，合起来 O(n+m)（见图 8）。

这笔交易的真实代价写在空间上：next 数组要吃掉 O(m) 的额外内存，且模式串一变就要重算。对短模式（m 很小）与一次性的匹配任务，BF 的常数更小、代码更短——KMP 的线性性在「同一模式反复匹配长主串」的场景才真正兑现。

额外优势：主串指针不回退意味着 KMP 只需要当前字符——适合流式数据（网络流、管道等无法回退的数据源）；BF 需要随机访问主串进行回退。这一特性偶尔作为选择题考点出现。

主串指针永不回退——模式串用自己的最长相同前后缀，替主串记住进度。

07严蔚敏经典题：T = "ababaaababaa" 的 next 与 nextval

考查方式：给定模式串手算 next / nextval，或由 next 数组反推模式串，也可作为字符串匹配综合题的第一步。具体分值随当年试卷结构与题号而定，本页不据此推断命题频率；作答前先核对题目采用的 next 下标约定。

第一步先求 next（从定义出发逐位写，不要跳步）：

j123456789101112

核验方法：next 逐位对照「最长相同前后缀 + 1」；nextval 逐位套用继承规则——j=5（a）与 T[next[5]]=T[3]=a 相同 → 继承 nextval[3]=0；j=6（a）与 T[next[6]]=T[4]=b 不同 → 保持 4。每步都能当场验算，考场不要跳步。

这道题考的不只是记忆：j = 7 是分水岭——T[1..6]="ababaa" 的最长相同前后缀从 3（"aba"）跌回 1（"a"），因为第 6 位多出的 "a" 打断了 "abab" 的延续。理解「为什么这里会跌」比背出 2 更重要，选择题变一下模式串就能分辨谁在背、谁在算。

约定对照（0-indexed 教材）：部分教材采用 0-indexed 约定——next 定义为最长相同前后缀长度（不加 1），next[0] = −1，成功位置 = i − m + 1。同一模式串的两套数值不同（如 "abab"：本页 1-indexed 下为 [0,1,1,2]，0-indexed 下为 [-1,0,0,1]）。作答前先确认题面使用哪套下标与 next 定义。

易错 · 继承的是 nextval，不是 next：T = "ababaaababaa" 的 nextval[6] = 4（T[6]=a 与 T[next[6]]=T[4]=b 不同 → 保持）。若把「继承 nextval[next[j]]」误写成「继承 next[next[j]]」，nextval[6] 会错算成 2——继承的是「优化后的值」，链条上每一步都已经跳过注定失败的比较。

变式 2 · 反推模式串：已知 next = [0, 1, 1, 2, 3, 4]（严蔚敏，6 位），求 T
从后往前next[j] 给出的条件已确定的前缀
j=6T[1..5] 最长相同前后缀 = 3T[1..5] 形如 "ababa"（最长 "aba"）
j=5T[1..4] 最长 = 2"abab" ✓（最长 "ab"）
j=4T[1..3] 最长 = 1"aba" ✓（最长 "a"）
j=3T[1..2] 无相同前后缀"ab" ✓

标准陷阱：第 6 位无法确定——next[6] 只由 T[1..5] 决定，T[6] 取任意字符都满足该 next 表。反推题若问「T 是什么」，答案必须写「前 5 位 "ababa"，第 6 位任意」；选具体字符的选项都是错的。

变式 3 · 选项辨析：T = "aaaaaa"，判断下列 next / nextval 说法
选项判定理由
next = [0, 1, 2, 3, 4, 5]正确"aa" 最长 "a"→next[3]=2，逐位递增 1

变式 4 · 重叠计数：统计 T = "abab" 在 S = "ababab" 中出现的次数（可重叠）——S[1..4] 全匹配后 j 不归 1，而是 j = next[4] = 2（重叠复用 "ab"），继续匹配在 S[3..6] 再命中一次，共 2 次。关键动作：匹配成功后由模式串自己记住重叠部分，一次扫描统计所有（含重叠）出现；BF 的对应做法是每轮起点 +1，同样成立但代价是 O(n×m)。

08RELATED 关联 · RELATED TOPICS

08KMP 在字符串算法谱系里的位置

KMP 不是孤立技巧：它是「用模式串自身结构加速匹配」这一思路的第一块里程碑。同族算法各付不同的账——

算法核心思想复杂度代价
BF逐个起点暴力比较O(n×m)零预处理、零空间
KMPnext 数组记忆前缀-后缀O(n+m)O(m) 空间，模式串变则重算
Rabin-Karp滚动哈希比较期望 O(n+m)哈希碰撞需回验（最坏 O(n×m)）
AC 自动机多模式：Trie + fail 指针（next 思想推广）O(n + Σm)建树空间大

关联考点①：KMP 的 next 与 AC 自动机的 fail 指针是同构思想——「失配时跳到最长的可复用后缀」；关联考点②：字符串哈希（RK）与 KMP 的取舍，408 大题偶尔给「哈希碰撞概率」做干扰项；关联考点③：最小循环节——若 T 的「长度 − next[n]」整除 n，则 T 由该循环节重复构成，这是 KMP 的经典应用题。

应试技巧 · 速算口诀与验算三连
口诀：「next 加一，nextval 继承」——next[j] = 最长相同前后缀 + 1；T[j] == T[next[j]] 时 nextval[j] 继承 nextval[next[j]]，否则保持。
考场 30 秒速算法：写 next 时把「T[1..j−1] 的最长相同前后缀」横着看——每行只在前一行基础上加一个字符，重叠要么变长 1、要么沿 next 链回退（方法二），不要每行重列全部真前缀真后缀。
验算三连：① next[2] 恒为 1（任何模式串）；② 全同字符段 nextval 应一路归零；③ next 数组中「非降段」后出现回落（如真题 j=7），回头检查是否漏掉了更短的重叠。
反推题思路：next[j] − 1 = T[1..j−1] 的最长相同前后缀长度——从后往前逐位锁定字符；第 n 位无法由 next[n] 确定（变式 2）。

09CODE 考点 · CODE IMPLEMENTATION

09三函数体系：getNext / getNextval / KMP

考点定位：408 代码题的高频形态——写出 getNext() / getNextval() / KMP() 三个函数，或给代码填空，大题分值 8–10 分。理解「next 构造 = 模式串自匹配」就能同时记住三个函数：它们共享同一个 while + if-else 骨架（见图 10）。

图 3 展示了匹配主循环，图 6 展示了 nextval 递推；还缺最容易被问的 getNext()——它的构造过程本身就是 KMP 匹配：模式串与自己做匹配，当 T[i] == T[j] 时，前缀 T[1..j] 与后缀 T[i−j+1..i] 相同，所以 next[i+1] = j+1；失败时 j 回退到 next[j]，与主匹配完全同构。

代码记忆要点（四条）：① 1-indexed——字符串从下标 1 开始，next[1] = 0，数组长度 m+1；② j == 0 统一——构造与匹配共用 j == 0 || 相等 分支，「主串前进、模式串归位」不需要单独代码路径；③ 构造与匹配同构——都是 while + if-else，区别只在 if 分支：构造写 next[i] = j，匹配写前进后判 j > m；④ nextval 额外判断——在构造 if 分支内增加 T[i] != T[j] 判断，相同则继承 nextval[j]，不同则赋 j（图 6）。

一句话总结：next[j] 告诉模式串「失败后跳到哪里」；nextval[j] 告诉它「跳过去如果还是同一个字符，就继续跳」。主串指针永远不需要回退——这就是 KMP 的全部精髓。
