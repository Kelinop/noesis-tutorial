01PROB. 原始问题 · BRUTE FORCE

01BF 的浪费：把已经验证过的字符再比较一遍

字符串模式匹配：在主串 S（长度 n）中找模式串 T（长度 m）首次出现的位置。最直观的是 BF（Brute Force）：从 S 的每个位置出发逐字符比较，失败则 S 指针回退到本轮起点 +1、T 指针归 1。用真实数据 S = "aaaaab"、T = "aaab" 走一遍（见图 1）：

原因

BF 失败时回退主串指针，丢弃已匹配部分的结构信息——「aa」已被验证，却从头再比。

↓
设计

KMP：利用模式串自身「前缀 = 后缀」的结构，失败时主串指针不动，模式串指针跳到 next[j]——已验证的部分由模式串自己记住。

BF 把已经匹配过的字符重新比较了一遍——浪费不在比较，在回退。
本质 · ESSENCE

本质钩：模式串替主串记住进度

02

当 S[i] 与 T[j] 失败时，我们已经知道 S[i−j+1 .. i−1] = T[1 .. j−1]。如果模式串自己存在「前 k−1 个字符 = 最后 k−1 个字符」的重叠，把模式串右滑到那个位置，重叠段自动对齐到 S 已匹配的部分——不需要重新比较，直接从 S[i] 与 T[k] 继续。主串指针 i 从不回退，回退的只有模式串指针。

这个模型的断裂点：主串不回退的保证依赖于「模式串的前缀-后缀信息预先算好」——这是 O(m) 的预处理，如果模式串每次变化都要重算，KMP 的收益就不存在。所以 next 数组必须「一次算出、反复使用」。

03NEXT 机制 · NEXT 数组

03next 数组：定义、手算与代码

定义 · 严蔚敏约定 1-indexed

next[1] = 0（哨兵值）；next[j] = T[1 .. j−1] 的最长相同前后缀长度 + 1；无相同前后缀（长度 0）时 next[j] = 1。

物理含义：当 T[j] 失败时，模式串指针应跳转到的位置——跳转后 T[1 .. next[j]−1] 与 S 对应位置的匹配已由前缀-后缀结构保证，无需重新验证。

定义只有一句话，但手算需要纪律。下面这组嵌套面板包裹一个完整的 worked example——T = "ababa" 的逐位推导（外层是语境，内层是内容，这是「定义 + 示例」的主从关系）：

每个位置都在回答同一个问题：「如果我在这里失败，之前匹配的部分里，有多长一段可以当作已经匹配好的前缀直接复用？」

「最长相同前后缀」本身值得一张图（见图 2）：以 T = "aaab" 的失败位置 j = 4 为例，T[1..3] = "aaa" 的最长相同前后缀是 "aa"（长度 2），所以失败后直接跳到 j = 3——前两个字符不用重比。

易错 · 两个最高频陷阱

① next[j] 是长度 + 1，不是长度——"aaa" 的最长相同前后缀是 "aa"（长度 2），但 next[4] = 3。考场上写出 2 即扣分。② next[2] 恒为 1：T[1..1] 只有一个字符，没有真前后缀——这是固定结论，直接写，不必推导。

有了 next 数组，匹配主循环只有三行（见图 3）。注意 j == 0 这个条件：它是哨兵——当 j 回退到 0 时，i、j 同时前进，「主串前进、模式串从头开始」不需要单独的代码路径。

成功时位置 = i − m（严蔚敏约定）：循环结束时 i 已指向匹配段之后。图 4 最后一步 i=7、m=4 → 位置 3。写成 i−j+1 也可以（此时 j=m+1，两式等价）——但考场上混用两种约定（0-indexed 与 1-indexed）是错位题的重灾区，先定约定再动笔。

04NEXTVAL 机制 · NEXTVAL 优化

04消除注定失败的比较

next 数组还藏着一处冗余：当 T[j] == T[next[j]] 时，S[i] ≠ T[j] 必然意味着 S[i] ≠ T[next[j]]——跳过去之后那次比较注定失败，却仍然在执行。nextval 的规则是：把注定失败的跳转「继承」掉（见图 5）。

优化规则 · nextval 递推

若 T[j] ≠ T[next[j]]：nextval[j] = next[j]（跳转有效，保持原值）。

若 T[j] == T[next[j]]：nextval[j] = nextval[next[j]]（跳过注定失败的比较，直接继承）。

nextval[1] = 0（哨兵不变）。注意：继承的是 nextval 的值，不是 next 的值——这是最高频的计算错误。

极端案例：模式串全为同一字符（T = "aaaaa"）时，next = [0,1,2,3,4,5]，但 nextval 全为 0——每个位置 T[j] 都等于 T[next[j]]，一路继承到 nextval[1]。失败时直接跳回开头，优化收益最大。反过来，nextval 与 next 完全相同（T 无任何字符重复）时，优化收益为零——这正是「优化不是免费的定理，是条件触发的增益」。

05COMPLEX 权衡 · COMPLEXITY

05O(n+m)：i 单调是线性性的全部秘密

为什么主串指针不回退就一定是线性的？因为 i 每轮要么 +1，要么原地等待 j 回退；而 j 每回退一次都跳到更小的位置，j 的总回退次数不超过总前进次数（O(n)）。匹配循环 O(n)、预处理 O(m)，合起来 O(n+m)。图 1 的真实账本：BF 12 次比较，KMP 8 次——省下的 4 次就是被遗忘的「aa」。

这笔交易的真实代价写在空间上：next 数组要吃掉 O(m) 的额外内存，且模式串一变就要重算。对短模式（m 很小）与一次性的匹配任务，BF 的常数更小、代码更短——KMP 的线性性在「同一模式反复匹配长主串」的场景才真正兑现。

06408 真题演练 · 408 STYLE

06严蔚敏经典题：T = "ababaaababaa" 的 next 与 nextval

这是 408 真题与严蔚敏《数据结构》反复出现的模式串。第一步先求 next（从定义出发逐位写，不要跳步）：

WORKED EXAMPLE · 手算 T = "ababaaababaa"
j123456789101112
T[j]ababaaababaa
next[j]011234223456
nextval[j]010104210104

核验方法：next 逐位对照「最长相同前后缀 + 1」；nextval 逐位套用继承规则——j=5（a）与 T[next[5]]=T[3]=a 相同 → 继承 nextval[3]=0；j=6（a）与 T[next[6]]=T[4]=b 不同 → 保持 4。每步都能当场验算，考场不要跳步。

这道题考的不只是记忆：j = 7 是分水岭——T[1..6]="ababaa" 的最长相同前后缀从 3（"aba"）跌回 1（"a"），因为第 6 位多出的 "a" 打断了 "abab" 的延续。理解「为什么这里会跌」比背出 2 更重要，选择题变一下模式串就能分辨谁在背、谁在算。

主串指针永不回退——模式串用自己的最长相同前后缀，替主串记住进度。
