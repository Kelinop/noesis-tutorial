对话 · DIALOGUE

对比 / 争论 / 误解纠正——两个立场交锋，正解从交锋中浮现

常见误解：「两次握手就够了——客户端发 SYN，服务器回 ACK，连接就建立。」
工程现实：服务器无法确认客户端收到了它的 ACK。如果客户端的 SYN 在网络中延迟后重放，服务器会为一个死连接分配资源。第三次 ACK 不是浪费——它是 双向确认的下界。
追问：「那四次握手不是更安全？」
工程现实：四次握手对双向确认是冗余的——三次是数学下界：一次太少（服务器不能确认），两次不够（客户端不能确认服务器的确认），四次多余。

档案面板 · ARCHIVAL PANEL

严格学术定义与固定规则陈述

定义

补码（Two's Complement）：对于 n 位定点整数，−X 的补码定义为 2ⁿ − X。算术上，补码将减法转化为「加模」——减一个数等于加它的补码再丢弃进位。

定义 · 约定

next[j]：模式串 P 的前缀 P[1..j] 中，最长相等前后缀的长度（严蔚敏约定 1-indexed）。next[1] ≡ 0——首字符失配时主串指针右移一位。

08CONTAIN.

陈述类容器 · L0 透明底，禁白底

本质钩 · ESSENCE HOOK

把 256 个数字摆在一个钟面上——0 到 127 是正数，128 到 255 是负数。加法是顺时针走，走够一圈就是减法。符号位只是告诉你站在钟的哪一半。

警示框 · WARNING BOX
⚠ 易错陷阱

next[1] ≠ 1。首字符失配时，模式串没有更短的前缀可以利用——next[1] 必须为 0（主串指针右移一位，模式串指针回到 P[1]）。考试中直接给 next[1] = 1 是最常见的错误。

洞察面板 · INSIGHT PANEL

应试技巧：next 数组手算三步法——① 写出模式串的所有前缀；② 对每个前缀找最长相等前后缀（不能是整个前缀本身）；③ 长度即为 next 值。验算：next[1] 必须为 0，next[length] 必然 ≤ length/2（鸽巢原理）。

内嵌面板 · INSET PANEL

G4 inset——附属/批注面板。内容从属于正文流。ink 边框，无圆角，L0 透明底。

10LAYOUT

横向构成 · Split / Staggered / Asym / Plate Row

Split · 对称双栏（等价内容并置，同基线无错位）

两次握手

客户端 → 服务器：SYN。服务器 → 客户端：ACK。服务器无法确认客户端是否存活——半开连接风险。

三次握手

客户端 → 服务器：SYN。服务器 → 客户端：SYN-ACK。客户端 → 服务器：ACK。双方各确认一次对方的序列号。

Staggered · 错位双栏（主从/先后，第二栏下移）

经典预言：光的能量与强度成正比。紫外光只要足够弱，也应不产生光电子。

实验事实：弱的紫外光立即产生光电子；强的红光无论照多久都不产生。频率才是门槛。

Asym · 非对称网格（主 2/3 + 窄 1/3，窄栏永远在右）

麦克斯韦方程组——四个方程统一了电学、磁学与光学。高斯定律描述电荷产生电场；高斯磁定律声明无磁单极子；法拉第定律描述变化的磁场产生电场；安培-麦克斯韦定律在安培环路定律上加入位移电流项，使方程组在电容器处也自治。
