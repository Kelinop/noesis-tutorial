01PROB. THE PROBLEM · BRUTE FORCE

01BF waste: comparing characters you already verified

String pattern matching: find the first occurrence of pattern T (length m) in text S (length n). The most direct approach is BF (Brute Force): start at every position of S and compare character by character; on failure, S's pointer retreats to the round's start +1 and T's pointer resets to 1. Walk through real data S = "aaaaab", T = "aaab" (see Fig. 1):

Cause

BF retreats the text pointer on failure, discarding structural information about the matched part — "aa" was verified, then recompares from scratch.

↓
Pressure

Worst case O(n×m): inputs with a long repeated prefix (S = "aaaaaaaaaab", T = "aaaab") make every BF round almost complete before failing.

↓
Design

KMP: exploit the pattern's own "prefix = suffix" structure — on failure the text pointer stays put, the pattern pointer jumps to next[j]; the pattern remembers what was already verified.

BF recompares characters it already matched — the waste is not in comparing, it's in retreating.
ESSENCE

Essence hook: the pattern remembers progress for the text

02

When S[i] and T[j] fail, we already know S[i−j+1 .. i−1] = T[1 .. j−1]. If the pattern has an overlap where its first k−1 characters equal its last k−1, slide it right to that overlap — the overlap auto-aligns with the verified part of S, and we continue directly from S[i] vs T[k] with no re-comparison. The text pointer i never retreats; only the pattern pointer does.

Where this model breaks: the no-retreat guarantee depends on prefix-suffix information computed in advance — an O(m) preprocessing. If the pattern changes often, the benefit disappears. next must be computed once and reused; KMP pays off when one pattern matches long texts repeatedly.

03NEXT MECHANISM · NEXT ARRAY

03next: definition, two hand-computation methods, code

Computing the next array is the single most-asked string task — given a pattern, find next, or reverse-engineer the pattern from next (variant 2 in §07); it is also the first step of any KMP application. This section gives the definition, two hand-computation methods, and code; traps and quick methods follow.

DEFINITION · YAN WEIMIN 1-INDEXED

next[1] = 0 (sentinel); next[j] = length of the longest common prefix-suffix of T[1 .. j−1], plus 1; no common prefix-suffix (length 0) → next[j] = 1.

Physical meaning: where the pattern pointer should jump when T[j] fails — after the jump, T[1 .. next[j]−1] is guaranteed to match the corresponding part of S by the prefix-suffix structure, with no re-verification.

Two hand-computation methods, cross-verify both: Method 1 (definition) — for each position, list the longest common prefix-suffix of T[1..j−1] and add 1; Method 2 (recurrence) — derive next[j] from next[j−1] (either next[j−1]+1 or walk back the next chain). The "longest common prefix-suffix" deserves its own figure (see Fig. 2): for T = "aaab" at failure position j = 4, T[1..3] = "aaa" has longest common prefix-suffix "aa" (length 2), so jump directly to j = 3 — the first two characters are never recompared.

TRAPS · THE TWO HIGHEST-FREQUENCY MISTAKES

① next[j] is length + 1, not length — "aaa" has longest common prefix-suffix "aa" (length 2), but next[4] = 3. Writing 2 on the exam loses the point. ② next[2] is always 1: T[1..1] is one character with no proper prefix-suffix — write it directly, never derive it.

With next computed, the matching main loop is three lines (see Fig. 3). The j == 0 condition is the sentinel: when j retreats to 0, i and j advance together — "text advances, pattern restarts" needs no separate code path.

BLUEPRINT CALLOUT · SENTINEL j = 0

j = 0 is not "comparing character 0" — it signals "no overlap left to retreat to": S[i] cannot match any T prefix, so advance i and j together and restart at T[1]. Without the sentinel, "retreat to the start" would need a separate branch.

05NEXTVAL MECHANISM · NEXTVAL

05Eliminating doomed comparisons: the inheritance chain

Mixing next and nextval is the classic way to separate "memorizers" from "computers" — given next, fill in nextval, or reverse the inheritance chain. "Inherit nextval, not next" is the standard distractor (variant 3 in §07).

next still hides one redundancy: when T[j] == T[next[j]], S[i] ≠ T[j] implies S[i] ≠ T[next[j]] — the comparison after the jump is doomed yet still executed. nextval's rule: inherit the doomed jump away (see Fig. 5).

RULE · NEXTVAL RECURRENCE

If T[j] ≠ T[next[j]]: nextval[j] = next[j] (the jump is effective, keep it).

If T[j] == T[next[j]]: nextval[j] = nextval[next[j]] (skip the doomed comparison, inherit).

nextval[1] = 0 (sentinel unchanged). Note: you inherit the nextval value, not the next value — the most frequent computation error.

Opposite extreme: a pattern with no repeated characters (e.g. "abcdef") has next ≡ nextval — every jump is effective, optimization gain zero. nextval removes structural redundancy; when the structure has none, it does nothing.

06COMPLEX TRADEOFF · COMPLEXITY

06O(n+m): monotonic i is the whole secret of linearity

Complexity appears as concept questions (is it O(n+m) or O(n×m)? "why is KMP faster than BF?"); deeper treatments ask for the monotonicity proof — the amortized argument (total j retreats ≤ total advances) is the core, and this section doubles as an answer template.

Why does a non-retreating text pointer guarantee linearity? Amortized argument: each round either advances i (match or sentinel) or waits while j retreats; every retreat moves j to a smaller position (next[j] < j), and j's advances are bounded by i's advances ≤ n — so total j retreats ≤ total advances = O(n). Matching O(n) + preprocessing O(m) = O(n+m) (see Fig. 8).

The real price is written in space: the next array costs O(m) extra memory and must be rebuilt whenever the pattern changes. For short patterns and one-off matches, BF has a smaller constant and shorter code — KMP's linearity pays off when one pattern matches long texts repeatedly.

Extra advantage: a non-retreating text pointer means KMP only needs the current character — suitable for streaming data (network flows, pipes that cannot rewind); BF needs random access to the text. A property worth remembering when choosing an algorithm.

The main-string pointer never retreats — the pattern uses its longest common prefix-suffix to remember progress for the text.

VARIANT TRAP · NEXTVAL INHERITS NEXTVAL

T = "ababaaababaa": nextval[6] = 4 because T[6]=a, T[next[6]]=T[4]=b differ → keep next[6]=4. Writing "inherit next[next[j]]" instead of "inherit nextval[next[j]]" turns nextval[6] into 2 — you inherit the optimized value; every link in the chain has already skipped doomed comparisons.

08RELATED RELATED TOPICS

08KMP in the string-algorithm family

KMP is not an isolated trick: it is the first milestone of "accelerate matching with the pattern's own structure". The family members each pay a different bill —

algorithmcore ideacomplexitycost
BFbrute-force every startO(n×m)zero preprocessing, zero space

Related ①: KMP's next and AC automaton's fail pointers are the same idea — "on mismatch, jump to the longest reusable suffix"; Related ②: hash-based matching (RK) vs KMP — RK's "hash collision probability" is a classic point of comparison; Related ③: minimal period — if n is divisible by n − next[n] + 1, the pattern repeats with that period; a classic KMP application.

Quick methods · 30-second method and triple verification
Mnemonic: "next adds one, nextval inherits" — next[j] = longest common prefix-suffix + 1; when T[j] == T[next[j]], nextval[j] inherits nextval[next[j]], otherwise keeps its value.
30-second method: read the "longest common prefix-suffix of T[1..j−1]" row by row — each row only appends one character to the previous, so the overlap either grows by 1 or retreats along the next chain (method 2); never re-list all prefixes and suffixes per row.
Triple verification: ① next[2] is always 1; ② an all-same segment's nextval must zero out all the way; ③ when next dips after a non-decreasing run (like j=7 above), check for a missed shorter overlap.
Reverse-engineering: next[j] − 1 = the longest common prefix-suffix of T[1..j−1] — lock characters backwards; character n itself is undeterminable from next[n] (variant 2).

09CODE CODE IMPLEMENTATION

09Three functions: getNext / getNextval / KMP

The core implementation task — write getNext() / getNextval() / KMP(), or fill in the blanks. Understanding "next construction = self-matching" lets you remember all three at once: they share one while + if-else skeleton (see Fig. 10).

Fig. 3 showed the matching loop and Fig. 6 the nextval recurrence; the most-asked piece is still getNext() — its construction is itself a KMP match: the pattern matches against itself, and when T[i] == T[j], prefix T[1..j] equals suffix T[i−j+1..i], so next[i+1] = j+1; on failure j retreats to next[j], exactly the main-loop skeleton.

CODE MEMORY · FOUR POINTS
  • 1-indexed: strings start at index 1, next[1] = 0, arrays sized m+1.
  • j == 0 unifies: construction and matching share the j == 0 || equal branch — "text advances, pattern restarts" needs no separate path.
  • Construction ≡ matching: both are while + if-else; the match branch writes next[i] = j here, advance-then-check-j > m there.
  • nextval's extra check: inside the construction match branch, test T[i] != T[j] — equal inherits nextval[j], different assigns j (Fig. 6).

One sentence: next[j] tells the pattern where to jump on failure; nextval[j] tells it "if the jump lands on the same character, keep jumping". The main-string pointer never needs to retreat — that is the whole essence of KMP.
